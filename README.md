# Cheat String Diff

Графическая оболочка для `cheat_string_diff.py`. Сравнивает дампы памяти Minecraft
с читом и без него и оставляет «упакованные» строки, которые есть только в cheat-дампах.
Из найденного одной кнопкой собирается YARA-правило.

## Как это устроено

| Часть | Язык | Что делает |
|---|---|---|
| `engine/cheat_string_diff.py` | Python | Ваш скрипт: чтение дампов, фильтры, вычитание clean-строк |
| `main.js`, `lib/engine.js` | JavaScript (Node) | Окно, запуск Python, проверка входных данных, запись файлов |
| `preload.js` | JavaScript | Узкий мост между окном и системой |
| `renderer/` | HTML, CSS, JavaScript | Интерфейс |
| `lib/yara.js` | JavaScript | Сборка `.yar` из выбранных строк |

Интерфейс и Python общаются так: Electron запускает движок с флагом `--json`,
а тот пишет в stdout по одному JSON-событию на строку (прогресс, результат).

## Скорость

Замер на пяти дампах по 220 МБ (всего 1,1 ГБ) на одном ядре:

| Версия | Время |
|---|---|
| Первая версия скрипта | 123 с |
| Сейчас | 55 с |

Итоговый список строк при этом тот же. Ускорение даёт не «магия», а три вещи:

- фильтр работает с байтами, а не со строками, проверки идут от дешёвых к дорогим;
- строка попадает в ответ, только если прошла фильтр, поэтому в остальных дампах фильтр
  не нужен: достаточно проверить, встречается ли там уже найденный кандидат.
  Полный разбор делается для одного дампа (самого маленького cheat), а не для всех;
- дампы и куски больших дампов обрабатываются параллельно (`--jobs`). Файл режется только
  по байтам, которые не могут быть частью строки, поэтому ни одна строка не разрывается.

Параллельность на многоядерном процессоре в песочнице, где я работал (одно ядро),
измерить было нельзя: там видны только накладные расходы (около 6%).

## Внешний вид

Окно разделено на две части и целиком помещается на экран без прокрутки: слева всё, что вы
вводите (дампы, параметры, запуск и прогресс), справа результат. До первого запуска справа
краткая схема «cheat минус clean», во время анализа крупный прогресс, потом таблица кандидатов.

- Цвета и размеры лежат в переменных в начале `renderer/style.css` (блок `:root`).
  Чтобы сменить главный цвет, поменяйте `--marker` (и `--marker-ink` для текста на нём).
- Шрифты Golos Text и JetBrains Mono лежат в `renderer/fonts` (лицензия SIL OFL),
  поэтому интернет не нужен.

## Запуск

Нужны Node.js и Python 3.8 или новее (при установке Python отметьте «Add to PATH»).

```
npm install
npm start
```

Если Python установлен в нестандартном месте, задайте путь в переменной окружения
`CHEAT_DIFF_PYTHON`.

## Как пользоваться

1. Перетащите в левую панель минимум два clean-дампа, в правую хотя бы один cheat-дамп.
2. Нажмите «Запустить анализ». Во время работы виден прогресс по каждому файлу, анализ можно отменить.
3. В таблице снимите отметки со строк, которые не годятся (например, случайный мусор).
   Работают поиск, фильтр по кодировке и сортировка.
4. Задайте имя правила и число совпадений, нажмите «Сохранить .yar» или «Сохранить .txt».

Строки в UTF-16 попадают в правило с модификатором `wide`, в ASCII с `ascii`,
найденные в обеих кодировках с `ascii wide`.

## Параметры фильтрации

Те же, что у скрипта: `--min-len`, `--min-entropy`, `--max-vowel-ratio`, `--min-unique`,
`--min-cheat-hits`. По умолчанию строка должна быть во всех cheat-дампах.
Чтобы поймать строки, которые меняются между сессиями, задайте 1.

## Скрипт по-прежнему работает из консоли

Без `--json` он ведёт себя как раньше:

```
python engine/cheat_string_diff.py --clean c1.dmp c2.dmp --cheat h1.dmp h2.dmp -o candidates.txt
```

Что добавлено: `--json` (события для интерфейса), `--limit` (сколько строк отдавать
интерфейсу, по умолчанию 100000, лучшие первыми), `--jobs` (сколько процессов использовать,
по умолчанию по числу ядер, не больше 8; 1 отключает параллельность).

Правила фильтрации и итоговый список строк не менялись: это проверяет `test/equivalence.py`
на эталоне (первая версия скрипта, `test/reference_engine.py`).

Одно отличие: если дамп не читается или пустой, анализ теперь останавливается с ошибкой.
Раньше скрипт писал предупреждение и шёл дальше, из-за чего нечитаемый clean-дамп молча
ослаблял исключение строк.

## Безопасность

Строки из дампов недоверенные: чит может положить в память что угодно. Поэтому:

- окно изолировано от Node.js (`contextIsolation`, `sandbox`, без `nodeIntegration`);
- строки выводятся только через `textContent`, никогда через `innerHTML`;
- политика CSP запрещает встроенные скрипты и внешние ресурсы, шрифты и иконки локальные;
- Python запускается без shell, пути и числа проверяются до запуска.

## Проверки

```
npm test                                   # движок, запуск, отмена, YARA (нужен только Python)
python test/equivalence.py                 # новый движок против эталона, включая границы кусков
python test/ui_check.py                    # интерфейс в Chromium (нужен playwright)
xvfb-run -a python test/e2e_electron.py    # настоящее приложение, Linux
```

## Сборка `.exe`

`npm run dist` собирает установщик. Python внутрь не входит: на компьютере, где будет
запускаться программа, должен стоять Python 3.8+. Чтобы обойтись без него, можно позже
превратить движок в `.exe` через PyInstaller и положить рядом.

## Известные ограничения

- Дампы читаются целиком через `mmap`; очень большие дампы обрабатываются долго,
  прогресс показывается по каждому файлу и общим процентом.
- Результат ограничен `--limit` строками (лучшие первыми); сколько всего найдено, видно в сводке.
